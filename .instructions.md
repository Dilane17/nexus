# 🏛️ Clean Architecture + Prisma v7 - Directives Backend NestJS

## 🎯 Principes fondamentaux

### 1. Structure Feature-Based

- Chaque domaine métier = 1 dossier feature
- `/features/{feature-name}/`
  - `domain/` → Entités, interfaces, cas d'usage
  - `application/` → Services applicatifs, DTOs
  - `infrastructure/` → Repositories, Query Handlers
  - `{feature}.module.ts`

### 2. Prisma v7 - Constantes obligatoires

```typescript
// TOUJOURS utiliser datasources explicites
super({
  datasources: {
    db: {
      url: process.env.DATABASE_URL, // Non-optionnel en v7
    },
  },
});
```

### 3. Pattern Repository obligatoire

- 1 repository = 1 entité
- Héritage de `BaseRepository<T>`
- Logique d'accès aux données centralisée

## 📋 Template Repository

```typescript
import { Injectable } from '@nestjs/common';
import { PrismaService } from '../../../shared/prisma/prisma.service';
import { BaseRepository } from '../../../shared/repositories/base.repository';
import { YourEntity, Prisma } from '@prisma/client';

@Injectable()
export class YourEntityRepository extends BaseRepository<YourEntity> {
  constructor(prisma: PrismaService) {
    super(prisma);
  }

  protected getSelectFields(): Prisma.YourEntitySelect {
    return {
      // Inclure les champs sûrs à exposer
      // Exclure les données sensibles
    };
  }

  async findById(id: string): Promise<YourEntity | null> {
    try {
      return await this.prisma.yourEntity.findUnique({
        where: { id },
        select: this.getSelectFields(),
      });
    } catch (error) {
      this.handlePrismaError(error);
    }
  }
}
```

## ✅ Règles absolues

### DO (À faire)

✅ Utiliser TypeScript strict mode

```json
{
  "compilerOptions": {
    "strict": true,
    "noImplicitAny": true,
    "noImplicitThis": true,
    "strictNullChecks": true,
    "strictFunctionTypes": true
  }
}
```

✅ Typer les retours de fonction

```typescript
async create(data: Prisma.UserCreateInput): Promise<User>;
```

✅ Utiliser les types générés Prisma

```typescript
import { User, Prisma } from '@prisma/client';
```

✅ Centraliser la gestion d'erreurs

```typescript
protected handlePrismaError(error: any): never {
  // Convertir Prisma errors → Domain errors
}
```

✅ Documenter les repositories

```typescript
/**
 * Repository User - Prisma v7 Clean Architecture
 * @method findById(id) - Récupère un user par ID
 */
```

### DON'T (À éviter)

❌ Ne pas utiliser `any`

```typescript
// MAUVAIS
async find(filter: any): Promise<any>

// BON
async find(filter: Prisma.UserWhereInput): Promise<User[]>
```

❌ Ne pas disperser la logique Prisma

```typescript
// MAUVAIS - Logique trop haut
export class UserService {
  async create(data) {
    return this.prisma.user.create({ data }); // ❌
  }
}

// BON - Via repository
export class UserService {
  async create(data) {
    return this.userRepository.create(data); // ✅
  }
}
```

❌ Ne pas exposer les secrets

```typescript
// MAUVAIS
select: {
  id: true,
  password_hash: true, // ❌ SECRET!
}

// BON
select: this.getSelectFields() // Contrôlé en BaseRepository
```

❌ Ne pas oublier les datasources v7

```typescript
// MAUVAIS - Causera P1012
super({
  log: [...]
});

// BON
super({
  datasources: {
    db: { url: process.env.DATABASE_URL }
  },
  log: [...]
});
```

    const created = await repository.create({ ... });

## 📊 Checklist avant un PR

- [ ] Tous les secrets sont exclus via `getSelectFields()`
- [ ] TypeScript strict mode ✅
- [ ] Tous les retours typés explicitement
- [ ] Pas de `any` utilisé sans justification
- [ ] Repository étend `BaseRepository<T>`
- [ ] Gestion d'erreurs centralisée
- [ ] Tests d'intégration présents
- [ ] Documentation JSDoc complète
- [ ] Datasources v7 configurées correctement
- [ ] Pas de `engine: classic` en production
